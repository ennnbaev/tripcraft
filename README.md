# TripCraft

AI trip planner: enter a destination, dates, budget and interests, get a day-by-day itinerary generated by an LLM. Regenerate any single day with feedback, save trips, track AI usage.

Full requirements: [docs/PRD.md](docs/PRD.md)

## Stack

- **Backend:** Java 21, Spring Boot 3.5, Spring AI 1.0 (OpenAI-compatible client), Spring Data JPA, Flyway
- **Database:** PostgreSQL 17 (JSONB for itineraries)
- **Frontend:** React 19, TypeScript, Vite, Tailwind CSS 4, TanStack Query, React Router
- **AI providers:** Google Gemini, Groq or OpenAI, switched by Spring profile

## Run everything in Docker

Requirements: Docker Desktop. Put your key into `.env` in the repo root (see `.env.example`), then:

```bash
docker compose up -d --build
```

Open http://localhost:3000. Postgres, the backend (profile from `SPRING_PROFILES_ACTIVE`, default `gemini`) and the frontend (nginx, proxies `/api` to the backend) run as containers. Without a key set `SPRING_PROFILES_ACTIVE=mock` in `.env`.

Useful commands: `docker compose logs -f backend`, `docker compose down` (data stays in the `pgdata` volume), `docker compose up -d --build` after code changes.

## Run locally (development)

Requirements: JDK 21, Node 22+ (Vite 8 does not run on Node 21), Docker. Maven is not needed: use the wrapper `./mvnw`.

```bash
# 1. Database only
docker compose up -d postgres

# 2. Backend (http://localhost:8080)
cd backend
export SPRING_PROFILES_ACTIVE=mock     # no key needed; or gemini / groq / openai
# AI_API_KEY: put it in the repo-root .env (see .env.example) or export it
./mvnw spring-boot:run

# 3. Frontend (http://localhost:5173)
cd frontend
npm install
npm run dev
```

Open http://localhost:5173. The footer shows "Backend: UP" when everything is wired.

### AI profiles

| Profile | Provider | Model | Key |
|---|---|---|---|
| `mock` | Built-in fake LLM (dev only), placeholder places | `mock-planner` | not needed |
| `gemini` | Google Gemini (OpenAI-compatible endpoint) | `gemini-3.5-flash-lite` | `AI_API_KEY` |
| `groq` | Groq | `openai/gpt-oss-120b` | `AI_API_KEY` |
| `openai` | OpenAI | `gpt-4o-mini` | `AI_API_KEY` |

Gemini model choice (Oct 2026): `gemini-2.5-flash` is closed to new API users, `gemini-3.8-flash` took 2+ minutes per itinerary on the free tier, `gemini-3.6-flash` about 23 s, `gemini-3.5-flash-lite` about 6 s. Change the model in `application.yml` if you want to compare.

The mock profile still goes through Spring AI `ChatClient`, so logging to `ai_requests` and the Stats page work the same way.
